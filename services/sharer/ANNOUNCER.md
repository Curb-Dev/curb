# CURB Telegram announcer

The announcer reads finalized public product events from Base and posts them
only to the public announcements channel, `@CurbAnnouncements`. It never posts
to `@CurbCommunity` or to the private operations alert chat.

## Owner setup

1. Open Telegram's official `@BotFather`, run `/newbot`, and keep the returned
   token private. Treat it like a password.
2. Add the bot to `@CurbAnnouncements` as an administrator. Grant **Post
   messages** only; leave every other administrator permission disabled.
3. In GitHub, open the repository's `sharing-mainnet` environment and create
   the Actions secret `ANNOUNCER_TELEGRAM` with this exact JSON shape:

   ```json
   {"token":"123456789:replace_with_the_BotFather_token","chatId":"@CurbAnnouncements"}
   ```

4. Run the `secrets-check` workflow once. Its announcer check validates the
   JSON and exact public destination without sending a channel message.

The scheduled `history-index` workflow runs the announcer after indexing. Its
state is stored in the existing data repository at
`sharing/8453/announcer/state.json` using `SHARING_DATA_REPO_TOKEN`. The first
run records the current safe block and sends no historical announcements.

If `ANNOUNCER_TELEGRAM` is absent, `npm run announce` is a dry run: messages
are printed, nothing is sent, and cursor state is not changed. Telegram errors
leave the event pending for the next run and do not fail the history-index job.

The only clickable links in public messages are generated by the service for
`https://curbfun.xyz/token/<address>` and `https://basescan.org/token/<address>`.
Names and symbols supplied by creators are normalized, clipped, HTML-escaped,
and rendered as Telegram code text so domains, mentions, and email addresses in
them cannot become links.
